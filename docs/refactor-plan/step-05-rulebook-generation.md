# Step 05 — Rulebook-driven generation

**Goal:** the rulebook is the SSoT *in practice*: the options class, the bareword verb table, the CLI
reference doc and the test manifest are generated from `effortless-rulebook.json`; `effortless build` in
the repo root regenerates them and the RuleSpeak docs; CI fails when a generated file drifts.

Inputs: `CliOptions`, `OptionCategories`, `ProjectFacts` (`help-*`), `TestCases`, `TestSuites`,
`RefactorSteps`.

## 1. `scripts/generate-from-rulebook.mjs` (Node ≥ 18, no dependencies)

Reads the rulebook and writes, deterministically (stable ordering, LF endings, trailing newline):

1. `src/Effortless.Cli.Core/Options/CliOptions.g.cs` — header comment `// <auto-generated> from
   effortless-rulebook.json — do not edit`; `[CommandLineManager(...)]` from `ProjectFacts.help-application-name`,
   `help-copyright`, `help-manager-description` (emit as a C# verbatim string, the stored value already
   contains literal `\n` sequences); one property per `CliOptions` row with `IsRetained == true`
   (compute retention from `Dispositions.IsRetained` — do not trust a cached column), in rulebook order,
   attribute `Description` = `HelpText` (C#-escaped), `MinOccurs = 0`, `Aliases` = `Aliases`; CLR type from
   `ValueType` (`bool`/`string`/`int`/`List<string>`). Must be byte-identical to the hand-written file from
   Step 3 — if not, fix the hand-written file (or the generator) until they agree.
2. `src/Effortless.Cli.Core/Options/BarewordVerbs.g.cs` — from `BarewordForms` of retained rows, preserving
   the verbs *as written* (case quirks included) and the `ConsumesNextArgAsTool` flag.
3. `docs/cli-reference.md` — grouped by `OptionCategories.SortOrder`; per option: flag, aliases, bareword
   forms, value type, help text, description; a "Removed in the rebuild" appendix listing dropped options
   with their `DispositionReason`; the exact `-help` syntax line; exit codes from `ExitCodes`; config files
   from `ConfigFiles` (retained); environment/keys from `EnvVariables`.
4. `tests/Effortless.Cli.E2E/TestManifest.g.json` — `[ { id, suite, priority, status, slow, interactive } ]`
   for every `TestCases` row whose suite `Kind` is `black-box`; and
   `tests/Effortless.Cli.Tests/TestManifest.g.json` for `unit`/`contract`.

`--check` mode: regenerate into memory and `diff` against disk; non-zero exit and a unified diff on drift.

## 2. Wire the repo's own `effortless.json`

From the repo root:

```bash
effortless install -execute "node scripts/generate-from-rulebook.mjs"
cd docs/rulespeak && effortless install rulebook-to-rulespeak -i ../../effortless-rulebook/effortless-rulebook.json
```

(`rulebook-to-rulespeak` exists in the live index; if its output shape is unhappy with the software-domain
rulebook, register `rulebook-to-markdown` instead and record which in `ProjectFacts`.) Commit the resulting
`effortless.json` and generated docs. `npm run generate` = `node scripts/generate-from-rulebook.mjs`;
`npm run build:docs` = `effortless build`.

## 3. Tests that enforce it (`devops` suite → implement as xunit facts in `Effortless.Cli.Tests`)

- `devops-generation-drift`: run the generator in `--check` mode from the test (spawn node) → exit 0.
- `devops-coverage-gate`: load the rulebook; assert no `CliOptions` row has `IsRetained && CountOfTestCases == 0`
  (compute both from raw data in the test — calculated fields are not materialized in the JSON).
- `devops-test-manifest`: reflect over the E2E and unit assemblies; every manifest id with priority P0/P1
  must exist as a `[Fact(DisplayName = "<id>: ...")]` (P2 may be `Skip` with a reason).
- Add a CI job `generate-check` that runs `node scripts/generate-from-rulebook.mjs --check`.

## 4. Rulebook hygiene

- Add a `scripts/validate-rulebook.mjs` (or reuse the MCP `validate_dag`) run in CI: JSON parses, single-line
  leaves, every FK resolves, every table/field has a Description, `TestCases.PrimaryOption` points at a
  retained option or the case is `blocked-by-decision`/deleted.
- Update `CLAUDE.md`: the only way to add/rename an option is a rulebook row + `npm run generate`.

**Done when:** `--check` passes, `effortless build` in the repo root is green and idempotent (second run
produces no diff), the three devops tests are green, `RefactorSteps.step-05.Status` → `done`.
